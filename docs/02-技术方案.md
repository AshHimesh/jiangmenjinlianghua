# 江门金量化 · 技术方案

> 版本：v1.0 ｜ 更新日期：2026-09-10

## 1. 技术选型

| 模块 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.11+ | AKShare 原生就是 Python 库 |
| 桌面窗口 | pywebview | 单进程、轻量，把网页界面装进原生 Windows 窗口 |
| 前端 | HTML + CSS + 原生 JS | 极简、无框架、易维护 |
| 行情数据 | AKShare | 免费开源 |
| AI 调用 | openai SDK + 自定义 base_url | 兼容所有 OpenAI 格式厂商 |
| 缓存 | SQLite | 本地轻量、零配置 |
| 打包 | PyInstaller | 打成单个 .exe |

## 2. 架构

```
[前端 HTML/JS 界面]
      ↕  pywebview JS Bridge（或本地 HTTP）
[Python 主程序]
  ├── AKShare 行情抓取
  ├── AI 调用（OpenAI 兼容）
  ├── Skill 管理
  └── 缓存（SQLite）
```

- 前端只负责界面展示与交互。
- Python 负责所有重活：行情抓取、AI 调用、缓存读写、Skill 管理。

## 3. 行情数据流
- 后端 `QuoteService` 后台线程**每 2 秒**并行抓取全部 14 个品种，缓存最新结果。

- 抓取失败时保留旧值并标记「数据延迟」，不崩溃。

## 4. AI 集成
- **支持服务商**：DeepSeek、智谱 GLM、Kimi、通义千问、OpenAI 等（凡支持 OpenAI 兼容接口的均可），另可选「自定义」手填地址。
- **用户配置项**：base_url（接口地址）+ api_key + model（模型名），保存到本地 `config.json`。
- **调用方式**：直连 `{base_url}/chat/completions`，`stream=True` 流式 (SSE) 接收，不依赖额外 SDK。
- **思考过程**：自动识别 `delta.reasoning_content` 字段（DeepSeek-R1、智谱 Z1、千问 QwQ 等推理模型），与正文分开累积，界面按网页 AI 的样式展示（流式思考 + 可折叠 + 思考耗时）。

### 4.1 流式架构（为什么要轮询）
pywebview 的 js_api 是「一问一答」式的，无法从 Python 主动推送。因此：

1. 前端调 `ask(问题, 当前品种)` → 后端立刻返回请求 id，并开后台线程流式接收。
2. 后端把「思考内容 / 正文」累积在内存缓冲里。
3. 前端每 120ms 轮询 `get_stream(id)`，取回当前累积内容并渲染。

效果与网页 AI 一致：思考过程和回答都是逐字出现的。

### 4.2 提示词结构与缓存
```
[system]  固定人设与要求      ← 内容稳定，可命中服务商的前缀缓存
[history] 历史多轮对话        ← 只追加，前缀稳定
[user]    【实时行情快照】+ 本次问题   ← 每次变化的部分放最后
```
把易变内容（行情快照）放在消息列表**最后**，前面稳定的前缀可被服务商的上下文缓存命中，降低成本。

### 4.3 AI 工具调用（阶段 6，Agent 模式）
除了自动注入的数据，AI 还可以**主动调用工具**按需取数（`src/tools.py`）：

| 工具 | 作用 |
| --- | --- |
| `get_kline(symbol, period, limit)` | 读取任意品种/周期的原始K线（最多 120 根），用于精确历史价位、逐根形态、跳空缺口 |
| `get_indicators(symbol, period)` | 读取任意品种/周期的完整技术指标 |
| `list_symbols()` | 查询品种清单及各自支持的周期 |

**实现要点**：
- **流式 tool_calls 累积**：OpenAI 兼容接口把 `tool_calls` 按 `index` 分片下发（一次调用可能跨多个 chunk），
  必须按 index 拼接 `id`/`name`/`arguments` 后再执行。
- **多轮循环**：执行工具 → 把 `assistant(tool_calls)` 与 `tool(结果)` 追加进 messages → 再次请求，
  直到模型不再调用工具为止（上限 6 轮，防死循环）。
- **优雅降级**：推理模型（如 `deepseek-reasoner`）多数不支持函数调用。
  一旦接口返回「不支持 tools」类错误，程序会**自动去掉工具重试一次**，
  并把该模型记入内存黑名单，后续请求直接走纯文本模式，用户无感知。
- **界面反馈**：工具调用过程实时展示（如「◌ 读取 螺纹钢 的日线K线」→「✓ 读取 螺纹钢 的日线K线」）。

### 4.4 两种模式的分工
| | 自动注入（阶段 3.5） | 工具调用（阶段 6） |
| --- | --- | --- |
| 覆盖范围 | 当前品种 + 问题提到的品种（最多3个）的全部周期 | 任意品种、任意周期、任意根数 |
| 模型要求 | 全部模型 | 需支持函数调用 |
| 成本 | 固定（可命中缓存） | 每次调用多一轮请求 |
| 定位 | **保底**：保证任何模型都能做多周期分析 | **增强**：AI 按需深挖 |

两者**同时开启**：先给基础数据，AI 觉得不够就自己调工具。

## 5. Skill 技能系统与缓存（阶段 4）

### 5.1 Skill 加载
- **目录**：`skills/`，支持 **.txt 与 .md** 两种格式。
- **默认**：目录下全部技能**自动激活**；可在 ⚙ 设置里逐个勾选启停。
- **导入**：设置面板点「导入技能文件」→ 系统文件框（`webview.create_file_dialog`）→ 复制进 `skills/`。
- **注入方式**：激活技能的**全文**拼进 **system 提示词**，并附强制声明——
  「你必须完整、认真地阅读全文，并严格按其角色定位、分析框架、执行步骤和输出格式来回答」。
- **缓存友好**：技能内容稳定不变，放在 system 前缀，可命中服务商的上下文缓存，长期成本极低。

### 5.2 已内置的默认技能
| 技能 | 文件 | 核心框架 |
| --- | --- | --- |
| 斐波那契短线入场专家 | `skills/斐波那契短线入场专家skill.txt` | 波浪理论 + 斐波那契多重汇聚 + 指标共振评分 + 15M/5M 精确入场 |
| 价格行为斐波那契专家 | `skills/价格行为斐波那契专家skill.txt` | 艾略特波浪计数 + 斐波那契回撤/扩展 + 价格行为确认 + 三路径推演 |

两个技能都要求 **MA20/MA40、MACD、RSI、KDJ、布林带、斐波那契回撤与扩展、多组汇聚区、背离**，
因此指标引擎（`src/indicators.py`）已相应扩展，并为 skill 做了专项优化：
- **MA40** 及 MA20/MA40 多空排列判断
- **斐波那契扩展位**（0.382/0.618/1.0/1.618 → 对应 TP1~TP4）
- **多组斐波那契汇聚区**：按**不同摆动腿数**计分（非按位次计），并过滤微小摆动噪声
- **背离检测**（MACD 柱 / RSI 与价格）
- **K线形态**（Pin Bar / 吞没 / Inside Bar）

### 5.3 相似问题缓存
- **存储**：`cache.db`（SQLite）。
- **命中策略**：
  1. 问题归一化（小写、去标点、**剔除虚词** 的/了/吗/呢…）
  2. 混合相似度 = `0.6 × 包含度 + 0.4 × 编辑比`，阈值 0.85
  3. 缓存键 = 归一化问题 + **当前品种** + **模型/技能指纹**
- **容错表现**（实测）：能正确命中「螺纹钢支撑位在哪 / 螺纹钢的支撑位在哪里？」（0.976），
  同时正确拒绝「螺纹钢**支撑**位在哪 / 螺纹钢**压力**位在哪」（0.750）—— 交易场景的关键区分。
- **失效**：20 分钟 TTL；换模型或改技能组合后自动失效。
- **界面**：命中时显示「⚡ 命中缓存 · N 分钟前的回答」并提供「重新生成」按钮（跳过缓存强制调用 AI）。

## 6. 多周期技术面分析（阶段 3.5）

界面**不显示K线**，但 AI 需要读K线才能做指标判断。为此新增三个模块：

| 模块 | 职责 |
| --- | --- |
| `src/kline.py` | 多周期K线获取 + 重采样 + 缓存 |
| `src/indicators.py` | 指标计算（MA/MACD/RSI/KDJ/BOLL/斐波那契/结构） |
| `src/analysis.py` | 品种识别 + 多周期报告生成 + 缓存预热 |

### 6.1 周期与数据源

| 周期 | 国内期货 | 国内指数 | 外盘商品 | 国际指数 |
| --- | --- | --- | --- | --- |
| 周线 | ✅ 日线重采样 | ✅ | ✅ | ✅ |
| 日线 | ✅ | ✅ | ✅ | ✅ |
| 12小时 | ✅ 1小时重采样 | ✅ | ❌ | ❌ |
| 4小时 | ✅ 1小时重采样 | ✅ | ❌ | ❌ |
| 1小时 | ✅ | ✅ | ✅ 仅当日 | ❌ |
| 15分钟 | ✅ | ✅ | ✅ 仅当日 | ❌ |
| 5分钟 | ✅ | ✅ | ✅ 仅当日 | ❌ |

- 数据源全部为**新浪**（`futures_zh_daily_sina` / `futures_zh_minute_sina` / `stock_zh_index_daily` /
  `stock_zh_a_minute` / `futures_foreign_hist` / 外盘分时接口 / `index_us_stock_sina` / 外汇日线接口）。
- 东方财富接口（`push2`、`push2his`）**按频率限流，实测不可靠，已全部弃用**。
- 国际指数的分钟线在免费源中确认无法获取（已试新浪、腾讯、同花顺、金十、和讯、东财）。

### 6.2 周期权重
提示词中明确告知 AI：**周线 > 日线 > 12小时 > 4小时 > 1小时 > 15分钟 > 5分钟**，
大周期定方向、小周期找时机，冲突时以大周期为准。

### 6.3 缓存策略
- 日线/周线：30 分钟；分钟线：5 分钟。
- 用户切换品种时，前端调用 `prepare()` **后台预热**该品种全部周期，提问时无需等待。
- 单次提问最多分析 3 个品种（当前查看的 + 问题中提到的），控制 token 消耗（实测约 1500–2000 tokens）。

## 7. 打包与部署（阶段 5）

### 7.1 目录分离原则
打包后，程序区分两类目录（见 `src/paths.py`）：

| 类型 | 开发时 | 打包后 | 内容 |
| --- | --- | --- | --- |
| **只读资源** | 项目根目录 | 程序内部（`sys._MEIPASS`） | `web/` 前端页面 |
| **用户数据** | 项目根目录 | **exe 旁边** | `skills/`、`config.json`、`cache.db`、`error.log` |

这样用户可以在 exe 旁边直接编辑配置、增删技能文件，而前端页面则被固定在程序内部。

### 7.2 打包方式
`build.py` 封装了 PyInstaller：

```
.venv\Scripts\python.exe build.py            # 文件夹模式（推荐）
.venv\Scripts\python.exe build.py --onefile  # 单个 exe
.venv\Scripts\python.exe build.py --console  # 保留控制台（排错）
```

关键参数：`--add-data web`（打包前端）、`--icon assets/app.ico`（程序图标）、
`--collect-all akshare/py_mini_racer/webview/pythonnet/clr_loader/curl_cffi`
（这些库有大量动态导入和原生依赖，必须整体收集）。

> ⚠️ **踩坑记录（务必保留 `--collect-all py_mini_racer`）**
> akshare 的 `futures_zh_spot()`（国内期货实时行情）内部用 `py_mini_racer` 这个 **V8 JS 引擎**生成随机数，
> 它依赖原生文件 `mini_racer.dll`（27.8 MB）与 `icudtl.dat`（10.3 MB）。
> 若不显式收集，打包后**国内 5 个期货品种实时行情会全部静默失败**（异常被容错逻辑吞掉，界面只显示"无数据"），
> 而 K 线却正常——非常隐蔽。这个问题是靠 `--selftest` 自检模式才定位到的。

打包完成后脚本会自动把 `skills/` 复制到产物目录，并生成 `使用说明.txt`。

### 7.2.1 程序图标
图标源图放在 `assets/icon.png`（竖版立绘）。运行 `tools/make_icon.py` 会：
1. 以**头部为中心做正方形裁剪**（原图 1279×1706 → 805×805 见方）；
2. 输出多尺寸 `assets/app.ico`（16/32/48/64/128/256），保证任务栏、桌面、文件管理器各处清晰；
3. 输出 `assets/icon_preview.png` 供肉眼核对裁剪效果；
4. 输出 `web/avatar.png`（128px），用于界面顶栏的圆形头像。

`build.py` 会自动检测 `assets/app.ico` 作为程序图标。**换图标只需替换 `assets/icon.png` 后重跑该脚本再打包。**

> ⚠️ **换图标后 Explorer 仍显示旧图标？这是 Windows 图标缓存，不是打包问题**
> Windows 图标缓存以「文件路径」为键。exe 路径没变时，即使文件里已经嵌入了新图标，
> 资源管理器仍可能沿用旧缓存。排查与解决：
> 1. 先确认图标真的进了 exe：`.venv\Scripts\python.exe tools\check_exe_icon.py`
>    （会列出 exe 内图标资源的全部尺寸，正常应看到 16/32/48/64/128/256 六项）；
> 2. 再重建图标缓存：`.venv\Scripts\python.exe tools\refresh_icon_cache.py`
>    （结束资源管理器 → 删除 `iconcache*.db` → 重启资源管理器；任务栏会短暂消失）。
>
> 本项目实测就遇到过：exe 内 6 个尺寸全是新头像，Explorer 却仍显示 PyInstaller 默认图标。

### 7.3 为什么默认用「文件夹模式」而不是「单个 exe」
- akshare + pandas + numpy + pythonnet + WebView2 加载器体积很大（数百 MB）。
- 单文件模式每次启动都要把全部内容解压到临时目录，**启动需数秒到十几秒**。
- 文件夹模式启动快、更稳定，且 `skills/` 本来就必须放在 exe 旁边供用户编辑，
  所以交付物本来就是一个文件夹。整个文件夹可直接压缩发给别人使用。

### 7.4 排错与自检
打包后没有控制台窗口，因此：

1. **启动异常** → 自动写入 `error.log`（exe 旁边）。
2. **功能自检** → 命令行执行 `江门金量化.exe --selftest`，
   程序会逐项检查（路径 / 前端资源 / 技能 / 14 品种行情 / 多周期K线 / 缓存），
   结果写入 `selftest.log`。**不弹窗口，适合排查"打包后某些功能不工作"的问题。**

## 8. 风险与兜底

### 8.1 全局网络超时保护（`src/netguard.py`）
akshare 及部分第三方库内部的 `requests.get(...)` **不设置超时**。一旦数据源不响应，
请求会**永久阻塞**：行情刷新线程被卡死（界面价格停止更新）、自检/分析流程挂起且无任何报错。

**实测踩坑**：打包后的自检进程运行 7 分钟仍无输出，就是这个原因。

**做法**：给 `requests.Session.request` 打幂等补丁，凡未显式指定 `timeout` 的请求自动注入
`(连接10秒, 读取25秒)`。`requests.get/post` 内部都走 `Session.request`，因此 akshare 的所有调用都被覆盖。
补丁在 `src/__init__.py` 中自动安装，任何入口都生效。

### 8.2 其它风险
- AKShare 对**国内**期货/指数实时性支持好；**国际**品种（现货金/银、原油、纳指、标普、美元指数）实时性需**逐一验证**，必要时用备用免费源兜底。
- 网络依赖：所有行情均需联网，断网时界面需有友好提示。
- 东方财富接口不稳定，所有数据源优先选用新浪；任一数据源失败时保留上一次的有效值并标记「数据延迟」。
- 国际指数的分钟线在免费源中确认无法获取（已试新浪、腾讯、同花顺、金十、和讯、东财）。

# 9. 阶段 7-9 技术设计（规划中，未实现）

## 9.1 金十 MCP 客户端（`src/mcp.py`）
按**标准 MCP 流程**实现，不依赖第三方 MCP SDK：

```
POST {serverUrl}   标准 JSON-RPC 2.0，Accept: application/json, text/event-stream
  1. initialize                → 从响应头取 Mcp-Session-Id
  2. notifications/initialized → 通知（无 id）
  3. tools/list / resources/list
  4. tools/call
```

技术要点：
- **传输**：Streamable HTTP。响应可能是 `application/json`，也可能是 SSE（`text/event-stream`），
  需按 `Content-Type` 分别解析（SSE 取 `data:` 行）。
- **会话**：把所有后续请求带上 `Mcp-Session-Id` 头。
- **结果读取**：优先 `result.structuredContent`；`result.content` 仅作可读文本补充。
- **分页**：统一 `cursor` 入参、`data.next_cursor` / `data.has_more` 出参。
- **错误分层**：`isError=true` 属业务错误；JSON-RPC `error` 属协议错误。
- **额度保护**：本地按「工具 + 北京时间自然日」计数，接近 1500 次时提示，避免打爆额度。

## 9.3 报告与图表（阶段 9）

### 9.3.1 图表生成流程
```
AI 分析（skill 驱动）
   ↓ 输出结构化标注数据（通过工具调用 render_analysis_chart）
{ symbol, period, waves:[{label,pIndex,price}],
  support:[...], resistance:[...],
  entry, stop_loss, take_profit:[...] }
   ↓
matplotlib 绘制：K线（自绘影线+实体）+ MA + 标注
   ↓
输出 PNG → 报告引用
```

**为什么让 AI 出结构、程序出图**：浪型判定与价位选择是 skill 的核心分析能力（AI 的强项），
而像素级绘图是程序的事。AI 只要给出「第几根是第几浪、关键价位是多少」即可。

### 9.3.2 绘图技术选型
- **matplotlib**：纯 Python，PyInstaller 打包成熟；不引入 mplfinance（自绘影线+实体足够，依赖更少）。
- **中文字体**：Windows 取 `C:\Windows\Fonts\msyh.ttc`（微软雅黑），
  找不到时依次回退 `simhei.ttf` / `simsun.ttc`，并在自检中报告字体是否可用（否则中文会变方块）。
- 图上标注：浪型序号直接画在对应K线附近；支撑压力/止盈止损画水平线 + 右侧文字标签。

### 9.3.3 报告格式
| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| Markdown + PNG 文件夹 | 便于二次编辑、可贴进任意笔记 | 图片与文本分离，转发不便 |
| **自包含 HTML**（图片内嵌 base64） | 单文件、双击即看、可浏览器打印成 PDF | 不便二次编辑 |

按 R9 最终以用户选择为准（见需求文档 5.3.3 待确认项）。
